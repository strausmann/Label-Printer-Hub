# Milestone 1.7.x — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone 1.7.x as the next free patch release with an empty milestone: the security and availability fixes (#234, #164, #166, #168, #256, #160) first, then the queue, print-confirmation, sheet, scanner and display fixes, the test and CI hygiene, and every finding of the five collection issues implemented or closed with evidence.

## Global Constraints

- **Patch milestone:** only `fix`, `docs`, `ci`, `chore`, `test`, `refactor`, `perf`. No `feat`, no `!`, no `BREAKING CHANGE:` footer.
- **Patch or feature (maintainer ruling 2026-11-19):** a new refusal that prevents a defect — a memory, DoS or security bound — is a `fix` (Tasks 2, 3, 10). A new setting, a new response field, a new user-facing capability or a data-model change (migration) is a `feat` and goes to the next minor milestone; this is why the queue cap of #168 is in 1.8.0 (#402): it comes with the `copies` migration. A task that turns out to need a `feat` stops and reports; it is not committed as `fix`.
- Commit scopes only from `commitlint.config.cjs`; subject lowercase, no full stop, ≤ 120 characters; every commit body ends with `Refs #<issue>` (several issues: one line each).
- Author `Björn Strausmann <projects@strausmann.ch>`. No `Co-Authored-By` and no `Claude-Session` trailer in this public repository.
- Branch: feature branches from `milestone/1.7.x`, PRs into it (squash). Before each task: `git fetch origin && git merge --no-edit origin/main` into `milestone/1.7.x` if `main` moved (Dependabot fixes keep landing there); re-check the task's line numbers after such a merge and after the task before it (Task 5 shifts `brother_ql_backend.py` by about three lines for Task 8). The milestone PR into `main` is merged with a merge commit and the standard subject `Merge pull request #N from strausmann/milestone/1.7.x` (the release guard recognises only that).
- English prose everywhere in the repository. No real hostnames, addresses or keys: examples use `example.invalid`.
- TDD: the failing test first; every new regression test is run once against the code without the fix (counter-test) and must fail **for the stated reason**. A test that is green from the start pins existing behaviour; it is marked "(guard)" and still gets a counter-test. Mutation paths (DB write, HTTP POST) test the happy path, the backend error path and the network error path.
- No `str(exc)` of an integration, upstream or device error in a response, a status cache row or an event (CWE-209); the class name only, the full exception in the server log.
- Tests that send requests through `create_app()` (its lifespan runs on the first request) live under `backend/tests/integration/`, whose autouse fixture provides the database (`tests/integration/conftest.py:34-89`). Pure middleware tests use a small app under `tests/unit/`, as `tests/unit/observability/test_access_log.py` does. Endless streams (SSE) are read with the `Stream` helper of `tests/integration/api/test_events_v1.py:66`, not with `ASGITransport` alone.
- A changed response shape: `cd frontend && pnpm gen:api`; `backend/tests/unit/api/test_route_auth_coverage_guardrail.py` and `backend/tests/api/test_openapi_completeness.py` stay green.
- A behaviour an operator notices gets an upgrade note in `website/src/content/docs/admin/upgrades/to-1-7-x.md` and `website/src/content/docs/de/admin/upgrades/to-1-7-x.md` (created by Task 1, linked from both `index.md`). Website pages change in English and German in the same commit, German with „du“, terms from `docs/glossary.toml`.
- UI tasks (13–18) load `taste-skill:design-taste-frontend` and `emil-design-eng` before building, `mobile-native` for phone layouts, `impeccable:impeccable` for acceptance. New strings: `pnpm i18n:extract`, German with „du“. Design tokens live in `frontend/src/design/tokens.ts` and `tokens.css` (checked against each other by `tokens.test.ts`); `index.css` only maps them to utilities.
- This machine has 4 cores: one implementer at a time; run the tests of the touched area during a task, the full gates once at the task's end: backend `ruff check . && ruff format --check . && mypy app/ && pytest`; frontend `pnpm typecheck && pnpm lint && pnpm test:coverage && pnpm build`, plus `pnpm e2e` for UI tasks.

## Review Focus

1. **A device error carries the tape address to a read key** (#234): the SNMP and TCP errors name the host, and the status route hands `last_error` to every key. → Task 1, `test_failed_probe_status_has_no_host`.
2. **The global body limit refuses a legitimate body** (#164): the Grocy route reads up to 1 MiB with `read_bounded`, a sheet-type import 64 KiB; the global limit must sit above both and must not touch a GET or the SSE stream. → Task 2, `test_one_mib_grocy_body_passes_the_global_limit`, `test_sse_stream_unaffected`.
3. **A recovered job prints although it was cancelled while rendering** (#168): the lazy render must stay outside the window between the state check and the `PRINTING` transition. → Task 4, `test_cancel_during_the_render_skips_the_job`.

5. **brother-ql-next sends 400 invalidate bytes for the QL-820NWB, the old package 200** (#256): a byte-exact test must be updated on purpose, not loosened, and the printer must still accept the job (device check). → Task 5, `test_ql820_raster_starts_with_400_invalidate_bytes`; Task 21 Step 2.

### Task 4: Restart recovery without rendering in the lifespan (#168)

**Files:**
- Modify: `backend/app/services/job_lifecycle.py:82-100` (`Job`), `backend/app/services/print_queue.py` (`_recover_printer` `:823-950`, the tape worker `:2580-2610`, `_take_group` `:3126-3165`, `retry_job` `:2263-2278`)
- Test: `backend/tests/unit/services/test_print_queue_lazy_recovery.py` (new), `backend/tests/integration/test_print_queue_recovery.py`

**Interfaces:**
- Produces:
  - `Job.rerender: Callable[[], bytes] | None = None` (`repr=False`). Recovery builds the wrappers without rendering (`image_payload=None`): `rerender` closes over the row payload and returns PNG bytes (`_rerender_from_db_payload` + `_serialize_image_to_png`). The cheap per-row checks of recovery (awaits confirmation, deferred, legacy payload) stay at startup.
  - `async def _materialise(self, job: Job) -> bool` in `PrintQueue`:
    1. `job.state != JobState.QUEUED` → return False at once, nothing rendered (a job cancelled before its turn stays in the asyncio queue until the worker's state check skips it).
    2. `image_payload` already set → return True.
    3. Otherwise `job.image_payload = await asyncio.to_thread(job.rerender)`; return True.
    4. The render raised: **after** the `await`, if `job.state` is still `QUEUED`, transition to `FAILED` (allowed, `job_lifecycle.py:48-55`) and `await self._store.mark_failed(UUID(job.id), f"recovery_rerender_failed: {exc.__class__.__name__}")`; if the state changed meanwhile (a cancel won), write nothing. Return False.
  - **Tape worker:** `await self._materialise(job)` right after the pause loop and before `if job.state != JobState.QUEUED: continue` (`:2591`); a False result → `continue`. Between that state check and `JobStateMachine.transition(job, JobState.PRINTING)` there stays no `await`, so a cancel during the render is honoured by the existing check.
  - **Recovered runs:** `_recovered_batch` (`:952-976`) is unchanged: it already builds `image_payloads=[m.image_payload or b"" for m in members]`, which is `b""` for a lazy member. `_take_group` (`:3126`), called group by group by `_process_batch` (`:2962`), materialises each member before its `PRINTING` transition: `job = self._jobs.get(str(jid))`; if `not await self._materialise(job)` → `continue` (the member is skipped like a cancelled one: a failed member is terminal, which `_RunSlot` already counts as over); else the payload is `job.image_payload` instead of `batch.image_payloads[idx]`. The transition right after it raises `InvalidStateTransitionError` for a member cancelled during its render, which `_take_group` already catches and skips.
  - **Retry:** `retry_job` copies `rerender` along with `image_payload`, so a retry of a recovered job that failed before rendering renders on its own turn.
