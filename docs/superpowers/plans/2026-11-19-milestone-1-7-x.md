# Milestone 1.7.x — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone 1.7.x as the next free patch release with an empty milestone: the security and availability fixes (#234, #164, #166, #168, #256, #160) first, then the queue, print-confirmation, sheet, scanner and display fixes, the test and CI hygiene, and every finding of the five collection issues implemented, closed with evidence or moved to 1.8.0 by name.

**Architecture:** Fixes stay inside the existing layers (schemas in `app/schemas/`, routes in `app/api/routes/`, logic in `app/services/` and `app/sheets/`, every print through `PrintService` and the queue, ADR 0005). Two structural changes: a pure-ASGI body limit installed in `create_app` (Task 2), and lazy re-rendering of recovered jobs so startup no longer scales with the backlog (Task 4). The frontend changes are pure functions with Vitest tests plus thin component edits.

**Tech Stack:** FastAPI / SQLModel / SQLite / Alembic / asyncio / pytest; React 19 + Vite + Vitest + Playwright, react-aria-components, TanStack Query/Router, lingui; GitHub Actions.

**Spec:** the issues of milestone 1.7.x with their comments (`gh issue view <n> --repo strausmann/labelyard --comments`) and the triage `docs/superpowers/plans/2026-11-19-milestone-1-7-x-triage.md`, which decides per issue and per finding what is in scope. Read both.

## Global Constraints

- **Patch milestone:** only `fix`, `docs`, `ci`, `chore`, `test`, `refactor`, `perf`. No `feat`, no `!`, no `BREAKING CHANGE:` footer. A task that turns out to need a new setting, a new response field or a migration stops and reports; it is not committed as `fix`.
- Commit scopes only from `commitlint.config.cjs`; subject lowercase, no full stop, ≤ 120 characters; every commit body ends with `Refs #<issue>` (several issues: one line each).
- Author `Björn Strausmann <projects@strausmann.ch>`. No `Co-Authored-By` and no `Claude-Session` trailer in this public repository.
- Branch: feature branches from `milestone/1.7.x`, PRs into it (squash). Before each task: `git fetch origin && git merge --no-edit origin/main` into `milestone/1.7.x` if `main` moved (Dependabot fixes keep landing there). The milestone PR into `main` is merged with a merge commit and the standard subject `Merge pull request #N from strausmann/milestone/1.7.x` (the release guard recognises only that).
- English prose everywhere in the repository. No real hostnames, addresses or keys: examples use `example.invalid`.
- TDD: the failing test first; every new regression test is run once against the code without the fix (counter-test) and must fail **for the stated reason**. Mutation paths (DB write, HTTP POST) test the happy path, the backend error path and the network error path.
- No `str(exc)` of an integration or upstream error in a response or log line (CWE-209).
- A changed response shape: `cd frontend && pnpm gen:api`; `backend/tests/unit/api/test_route_auth_coverage_guardrail.py` and `backend/tests/api/test_openapi_completeness.py` stay green.
- A behaviour an operator notices gets an upgrade note in `website/src/content/docs/admin/upgrades/to-1-7-x.md` and `website/src/content/docs/de/admin/upgrades/to-1-7-x.md` (created by the first task that needs it, linked from both `index.md`). Website pages change in English and German in the same commit, German with „du“, terms from `docs/glossary.toml`.
- UI tasks (13–18) load `taste-skill:design-taste-frontend` and `emil-design-eng` before building, `mobile-native` for phone layouts, `impeccable:impeccable` for acceptance. New strings: `pnpm i18n:extract`, German with „du“.
- This machine has 4 cores: one implementer at a time; run the tests of the touched area during a task, the full gates once at the task's end: backend `ruff check . && ruff format --check . && mypy app/ && pytest`; frontend `pnpm typecheck && pnpm lint && pnpm test:coverage && pnpm build`, plus `pnpm e2e` for UI tasks.
- Every finished task ticks its box in the issue (or the finding's box in a collection issue) with the commit.

## Review Focus

1. **The global body limit refuses a legitimate body** (#164): the Grocy route reads up to 1 MiB with `read_bounded`, a sheet-type import 64 KiB; the global limit must sit above both and must not touch a GET or the SSE stream. → Task 2, `test_one_mib_grocy_body_passes_the_global_limit`, `test_sse_stream_unaffected`.
2. **A recovered job prints after a job submitted during startup** (#168): lazy rendering must keep the order of the persisted rows and the startup pause. → Task 4, `test_recovered_jobs_keep_their_order`, `test_paused_printer_prints_no_recovered_job`.
3. **A QL printer cannot be created on a fresh process** (#166 with #207): model validation on create asks the `ModelRegistry`, which knows the QL driver only after its module is imported. → Task 3, `test_create_ql_printer_on_a_fresh_registry`.
4. **The tape address still reaches a read key through another route** (#234): the SSE snapshot, the status route and the job routes. → Task 1, `test_no_route_shows_a_tape_address_to_a_read_key`.
5. **brother-ql-next sends 400 invalidate bytes for the QL-820NWB, the old package 200** (#256): a byte-exact test must be updated on purpose, not loosened, and the printer must still accept the job (device check). → Task 5, `test_ql820_raster_starts_with_400_invalidate_bytes`; Task 22 Step 2.
