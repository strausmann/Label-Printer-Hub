## Global Constraints

- **Repo rules.** Public repo: English identifiers, comments, commits, PR text; Conventional Commits; **no AI attribution** (no `Co-Authored-By: Claude`, no session links, no "Generated with" footer); commits are authored with the maintainer's git identity. Never `git add -A`; stage explicit paths and read `git status --short` before every commit.
- **Execution order.** 0, 1, 1b, 2, 3, 4, 5–14, **21** (#279 before the UI tasks), 15, 16, 17, 18, 19, 23a, 23b, 24–30.
- **Release model (operator, 2026-11-11).** Patch milestones are titled `<major>.<minor>.x` (this one: **`1.5.x`**, branch **`milestone/1.5.x`**); minor milestones stay `x.y.0`. Dependabot PRs and single fixes may land on `main` at any time — **no pauses**. Dependabot commits are `chore(deps)`/`ci(deps)`, which `.releaserc.json` maps to `release: false`; a patch release from `main` (1.5.1, 1.5.2, …) therefore only comes from a `fix` (or `perf`) commit there, e.g. a security fix or a hand-written fix on top of a Dependabot update. The milestone PR gets the next free patch number when it is merged. After every patch release from `main`, `main` is merged back into `milestone/1.5.x` (recurring step R1 below).
- **Branch.** Work lands on `milestone/1.5.x` (one commit per task step, as in 1.5.0). Exceptions: Task 1 (PR #270 retargeted into the milestone), Task 1b (PR #269 retargeted into the milestone), Task 21 (#279 PR into the milestone). Before each task: `git branch --show-current` = `milestone/1.5.x`, `git pull --ff-only`.
- **Commit types.** `fix`, `perf`, `refactor`, `test`, `docs`, `ci`, `chore`, `build` only. **No `feat`, no `!`, no `BREAKING CHANGE:` — in any task, any merged PR (#269, #270, #279) and the milestone PR title** (D1). A finding that turns out to need a new capability is deferred to 1.7.0, not shipped as `fix`. Checked mechanically in Task 25.
- **Commit messages.** The repo has no local commit hooks and no root lockfile; commitlint runs in CI (`.github/workflows/commitlint.yml:22-28`). Check each message the same way CI does: once per clone `npm install --no-save --ignore-scripts @commitlint/cli@19 @commitlint/config-conventional@19` at the repo root (`node_modules/` is gitignored), then `echo "<msg>" | npx commitlint --config commitlint.config.cjs`. **Scopes only from the enum** in `commitlint.config.cjs:23-57` (e.g. `plans`, `license`, `printer-backends`, `printers`, `ui`; no `ipp`, `runtime`, `i18n`, `licences`).
- **Finding IDs in commits (mandatory).** Every commit of Tasks 5–18 names the finding IDs it handles in its body (`Refs 263-31, 263-37`); Task 19 checks it.
- **Fix, not feature.** Each task that adds a setting, an error code, a response field or a stricter permission says in one sentence why it is a fix (it closes a defect or a gap in an existing promise) — see the "Why fix" line in Tasks 6, 9, 10, 11, 12, 15, 23a. Every API contract change is listed in the release notes' upgrade notes (Task 30).
- **Tests.** Every regression test goes red against the unfixed code (counter-test), for the right reason; record the run in the task report. Behaviour tests over text scans; a source-text guard names its limits, reports file:line and says why no behaviour test is possible.
- **Backend checks (per task, per directory).** `ruff check .`, `ruff format --check .`, `mypy app/`, `pytest <touched dirs> -m "not slow"`. Full suite only in Task 25.
- **Frontend checks (per task).** `pnpm typecheck`, `pnpm lint`, `pnpm test -- <touched files>`, `pnpm e2e -- <touched specs>`. Full chain only in Task 25.
- **Generated schema.** `frontend/src/api/schema.gen.ts` only via `pnpm gen:api`; CI checks drift (`.github/workflows/ci.yml:171-174`).
- **i18n.** Every new or changed UI string in `frontend/src/i18n/locales/en/messages.po` and `de/messages.po`; German in **du**, real umlauts. Removed strings leave both catalogues.
- **UI task protocol (Tasks 15, 16, 17, 21, 24).** Before writing UI code load `taste-skill:design-taste-frontend`, `emil-design-eng`, `mobile-native` (and `break-ui` for lists and cards). Check every changed screen at 1280 × 800 and 390 × 844, light and dark, and at the short "keyboard open" viewports from #279 (1280 × 500, 390 × 400) for anything with a text input. Screenshots are artifacts, not a gate (existing `SHOTS` pattern, `frontend/e2e/shell.spec.ts`).
- **Privacy.** No real hostnames, IPs, serials, names or tokens in code, fixtures, screenshots, issues or commits (`docs/policies/privacy.md`; CI `privacy-scan`). Trademark rules: `docs/policies/trademarks.md`.
- **Agent limits.** Each command under 170 s; long suites in the background with a watcher; commit as soon as the fast checks are green.
- **Baselines.** Any count handed to a worker (tests, lint messages) is quoted with the commit it was measured at.

## Review Focus

1. **A released milestone with an open issue.** The guard must see issues *and* exclude pull requests (the issues API returns both), page through more than 100, and fail closed when the API errors (Task 2 `test_open_pull_request_in_milestone_is_ignored`, `test_api_error_blocks_release`).
2. **A sheet discard by a printer-restricted `print` key after the scope change.** 403 with the documented error code, no state change, no event (Task 11 `test_discard_requires_admin`).
3. **A webhook arrives while the target printer has no tape or is disabled.** The caller gets the same 409 as `POST /api/v1/print`, no job row is left `queued` (Task 12 `test_webhook_without_tape_is_409_and_leaves_no_row`).
4. **GHCR cleanup deletes a tag someone still pulls.** Kept set is exactly `dev`, `latest`, releases ≥ 1.4.0 with floating tags, open previews; the controller checks a real dry run on `main` against the keep rule before the first deletion, and nothing younger than a day is a candidate (Tasks 1b, 30).
5. **German strings rewritten to du change meaning or break plural forms.** Catalogue compiles with `--strict`, every changed msgid keeps its placeholders (Task 17 `test_placeholders_survive_du_rewrite`).

**Rulings:**
- **Content type `qr_two_lines`**: the old payload carried exactly a title and a QR payload; `qr_two_lines` renders primary id + title + QR from the plugin lookup.

Today the webhook does not map `LookupFailedError` itself; the shared mapping fixes that.
- **Rate limit:** one bucket **per webhook API key** (key `("webhook", sha256(key)[:16])`, shared by both routes — not per route), consumed **after** `require_webhook_key` succeeded (an unauthenticated call never uses a token), `limit_per_minute = settings.webhook_limit_per_minute`, default **120** (Spoolman and Grocy do not retry, so bulk events must pass); over → 429 `rate_limit_exceeded` with `Retry-After`, the shape of `_enforce_key_rate_limit` (`auth/dependencies.py:161`).
