# Milestone 1.7.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship milestone 1.7.0 with an empty milestone: SNMP discovery in the printer form with a write-only community (#296), a cart that checks every item before printing (#285), the webhook quantity on the label in the hub's language (#284), Grocy's label printer webhook and Grocycode scanning (#281), bulk resolve of unconfirmed sheet cells (#282), admin keys without printer restrictions (#283), the notification centre (#255, design approved 2026-11-14) and a permanent cart icon with count (#316).

**Architecture:** Backend changes stay inside the existing layers: schemas in `app/schemas/`, routes in `app/api/routes/`, logic in `app/services/` and `app/sheets/`; every print goes through `PrintService` and the queue (ADR 0005). The Grocy label route answers within 1.5 s and completes its job after the response (deferred printing). The frontend adds one pure function per feature (payload, preview selection, notification derivation, Grocycode parsing) with Vitest tests, and thin components on top. The notification centre derives its entries in the browser from queries the SSE stream already keeps live.

**Tech Stack:** FastAPI / SQLModel / SQLite / Alembic / asyncio / pytest; React 19 + Vite + Vitest + Playwright, react-aria-components, TanStack Query/Router, lingui.

**Spec:** `docs/superpowers/specs/2026-11-14-milestone-1-7-0-design.md` (section and ruling numbers below refer to it). Issues: `gh api repos/strausmann/Label-Printer-Hub/issues/<n>` and `/comments`.

**Revision 2 (2026-11-14):** plan review of `c988990` (NEEDS_FIXES, C0–C18 and F1–F9) applied; maintainer rulings on Q1–Q6 and #316 applied; controller rulings on the Grocy time budget (1.5 s, deferred printing), the 1 MiB bounded body, the Grocy URL exposure (reduce on our side, upstream report is Q7) and C1.

## Global Constraints

- Minor milestone: `feat` commits allowed; **no `!`, no `BREAKING CHANGE:` footer**; no removed or renamed response field, **except** the two maintainer rulings of 2026-11-14: `connection.snmp.community` is no longer returned (replaced by `connection.snmp.community_set`, #296), and `allowed_printer_ids` on a key with the admin scope is refused with 422 (#283). Both get an upgrade note in the release notes; neither carries `!` or a BREAKING footer.
- Commit scopes only from `commitlint.config.cjs` (`api`, `ui`, `webhook`, `sheets`, `printers`, `auth`, `security`, `docs`, `decisions`, `plans`, …). Subjects lowercase, no full stop, ≤ 120 chars. Every commit body ends with `Refs #<issue>`.
- Branch: work on `milestone/1.7.0` (feature branches from it, PRs into it). Before each task: `git fetch origin && git merge --no-edit origin/milestone/1.6.0` while 1.6.0 is unreleased, `origin/main` after; re-check the task's file paths after a merge that touched them.
- Prose names Labelyard; settings `LABELYARD_*` (the `PRINTER_HUB_*` fallback stays); browser storage keys keep `lph.` (R-0-1).
- TDD: the failing test first; every new regression test is run once against the code without the change (counter-test) and must fail **for the stated reason**.
- Mutation paths (HTTP POST, DB write) test the happy path, the backend error path and the network/upstream error path.
- No `str(exc)` of an integration or upstream error in a response (CWE-209). Example hosts use `example.invalid`.
- Every new route: OpenAPI responses documented, `cd frontend && pnpm gen:api` regenerates `src/api/schema.gen.ts`, `backend/tests/unit/api/test_route_auth_coverage_guardrail.py` and `backend/tests/api/test_openapi_completeness.py` stay green.
- A raw request body is read only with `read_bounded` (Task 7), never `await request.body()`.
- Website pages change in English and German in the same commit (`website/src/content/docs/…` and `website/src/content/docs/de/…`), glossary terms from `docs/glossary.toml`, German with „du“. Upgrade notes go to `website/src/content/docs/admin/upgrades/` (en + de) and the release PR body.

A new dialog, popover or panel gets a case in `frontend/e2e/short-viewport.spec.ts` (1280x500 and 390x400, keyboard covering the visual viewport). New UI gets its README screenshot (`pnpm screenshots`, view listed in `frontend/e2e/readme-screenshots.spec.ts`).

- Gates per task: backend `ruff check . && ruff format --check . && mypy app/ && pytest`; frontend `pnpm typecheck && pnpm lint && pnpm test:coverage && pnpm build`, plus `pnpm e2e` for UI tasks.

## Review Focus

1. **The Grocy route waits for the printer** (#281): the SNMP preflight takes up to 3 s per try, Grocy gives up after 2 s and then shows the URL with the token to its user. → Task 8, `test_slow_preflight_does_not_delay_the_response`.
2. **A body without `Content-Length`** (#281): a chunked 20 MiB body must stop at the limit, not be buffered. → Task 8, `test_chunked_body_stops_after_limit`.
3. **A token in the access log or a 422 body** (#281): uvicorn's access record carries the query in its args; a constrained `Query` echoes its input; an encoded parameter name would slip past the filter. → Task 7, `test_access_record_token_is_redacted_in_args`, `test_encoded_parameter_name_is_not_a_token`, `test_create_app_installs_query_token_redaction`.
4. **A printer with a custom SNMP community** (#296): discovery works, but printing fails as "offline" if the preflight still asks with `public`. → Task 1, `test_preflight_uses_stored_community`.
5. **More than 200 jobs in a day** (#255): the newest failure must be in the notification centre. → Task 13, `test_list_jobs_newest_returns_the_latest_200`.
