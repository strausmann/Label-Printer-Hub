# Milestone 1.8.0 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship release 1.8.0 (sheets and calibration made checkable) with all 22 issues of the milestone implemented or closed with evidence, an upgrade from 1.7.1 without data loss or manual step, and every new API surface additive except the loosenings and tightenings the spec names.

**Architecture:** Fixes and features stay inside the existing layers: schemas in `app/schemas/`, routes in `app/api/routes/`, logic in `app/sheets/`, `app/calibration/`, `app/services/`, every print through `PrintService` / the queue (ADR 0005). New units: a shipped sheet-type catalog (`app/catalog/`, ADR 0028) that replaces seeding; calibration runs, history and check sheets (`app/calibration/runs.py`, `history.py`, `check_sheet.py`, ADR 0029); one margin-placement function that cuts bands into zone-free rectangles and is shared by plan, preview, margin check and probe page. Seven migrations (E1, A2, A1, C1, C2, D1 plus the A3 startup step) in one linear chain.

**Tech Stack:** FastAPI / SQLModel / SQLite / Alembic / asyncio / pytest (+ hypothesis where a property test is named); `segno`/the existing QR builder for `LYC1` codes; React 19 + Vite + Vitest + jsdom + Playwright, react-aria-components, TanStack Query/Router, lingui; semantic-release with `@semantic-release/exec`; GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-21-milestone-1-8-0-design.md` (at `5c5ed685` or later) — the binding authority; every "spec 7.2" below is a section of it. Approved mockups: `docs/designs/1.8.0/README.md` at `d50b3c72`. Read both before a task; read every file a task names before changing it. Line numbers refer to `main` at `40bb6566` (equal to `main` when this plan was written); re-check them after each merge.

## Review Focus

1. **A printer-restricted key on the new per-printer surfaces.** A key limited to printer P must see only P in `GET /sheet-types/{key}/id-placement`, the run picker data, calibration history, the probe routes and the stored-label read of a cell whose job ran on another printer; a reasonable person expects the same filter as `/api/v1/jobs/{id}` (`jobs.py:122-145`). → Task 10a `test_id_placement_lists_only_the_keys_printers`, Task 13b `test_history_of_another_printer_is_403_for_a_restricted_key`, Task 17a `test_restricted_key_on_another_printer_is_403`, Task 19a `test_cell_label_read_needs_only_sheet_read_scope` (guard: the label is sheet data, same scope as the sheet).
2. **German decimal comma in every new millimetre field**, not only the readings: zone x/y/w/h, ID offset, purge days stay integers. A typed `12,5` must give 12.5 mm, never 125 or an error. → Task 10b `zone editor accepts a decimal comma`, `offset stepper accepts a decimal comma`; one shared parser `parseMm` (Task 15b) is reused by 10b — 10b creates it, 15b imports it.
3. **A `web_url` with a path prefix or a trailing slash** (`https://inventory.example.invalid/snipe/` behind a proxy): links and printed QR payloads must keep the path and never contain `//` after the host or drop the prefix. → Task 5a `test_web_url_with_path_prefix_keeps_the_prefix`, `test_trailing_slash_gives_no_double_slash`.
4. **Purge or delete racing a stored job that references the row**: a retry of a job whose sheet was purged, or a job whose sheet type was deleted, must fail with the existing "sheet not found" error, never a 500, and the job view says "sheet purged". → Task 6a `test_retry_of_a_job_whose_sheet_was_purged_is_a_clean_error`; Task 8c guard `test_delete_of_a_type_without_sheets_leaves_page_jobs_readable` (a type with sheets is refused anyway; what remains are calibration and probe job rows naming the deleted type, which must still list and show their detail).
5. **Double submit of a one-shot admin action** (double click, retried request): install from the catalog, delete-unused, history restore, release-cells and purge must each change state once; the second call answers 409 or reports nothing changed, never a duplicate row or a second counter step. → Task 8c `test_concurrent_install_gives_one_type_and_one_409`, Task 13b `test_restore_twice_writes_two_entries_with_equal_values` (two restores are two decisions; documented, not deduplicated), Task 20 `test_second_release_changes_nothing`, Task 6a `test_purge_twice_reports_empty_the_second_time`.
