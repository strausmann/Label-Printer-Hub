Labelyard 1.7.0 is a feature release. Your data, keys and settings carry over; update the tag as described in [Tags and updating](/admin/upgrades/). Check the points below if a script or integration reads printer data from the API or creates API keys.

## The SNMP community is no longer returned

The SNMP community works like a password for the printer's status. From 1.7.0 no printer response shows it.

- `GET /api/v1/printers`, `GET /api/v1/printers/{id}` and the admin printer routes report `connection.snmp.community_set` instead of the community: `true` when a community is stored.
- To change the community, send it as before in `connection.snmp.community`. Leave it out, or send `null`, to keep the stored one. A new printer without a community gets `public`.
- If you change the printer's host or port, send the community again. Without it the hub answers `422` with `snmp_community_required` and saves nothing, so a stored community never goes to a new address.
- The print check before each job now uses the stored community, the same one as status discovery. A printer with its own community no longer shows up as offline when you print.

If a script reads `connection.snmp.community`, it now finds no value. Read `community_set` instead.

## Admin keys act on every printer

A key with the `admin` scope always acts on every printer. A printer list on such a key never had a use for admin routes, and it kept an admin key from printing on other printers. From 1.7.0 the hub ignores the list on an admin key.

- A key you created with the `admin` scope and a printer list loses that restriction. It works on every printer, and the key list shows the stored list as ignored. To remove the stored list, send `{"allowed_printer_ids": []}` to `PATCH /api/v1/admin/api-keys/{id}`.
- Creating an admin key with a printer list, or adding a printer list to an admin key, answers `422` with `admin_key_not_restrictable`. Nothing is saved. Leave the list out, or create a `print` key if the key must stay on some printers.
- `read` and `print` keys keep their printer list.

If you want an admin key that is limited to some printers, replace it with a `print` key for those printers and keep a separate admin key for yourself.
